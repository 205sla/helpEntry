# 디자인 요청서 — 엔트리 질문 채널 안내 페이지

> 이 문서는 디자이너 AI에게 전달할 페이지 디자인 요청서입니다.
> **콘텐츠/구조/기능 요구사항만 명시**하며, 시각적 디자인 결정(색상·폰트·레이아웃·일러스트·모션 등)은 모두 디자이너의 재량에 위임합니다.

---

## 1. 프로젝트 개요

### 1.1 페이지 목적
한국 코딩 교육 플랫폼 **엔트리(Entry)** 를 사용하는 학생들이 코딩 중 막히는 문제를 효과적으로 질문할 수 있도록 적합한 채널(카카오톡, 밴드, 디스코드 등)을 안내하고, 답변을 빠르게 받기 위한 질문 작성 가이드를 제공하는 단일 페이지 웹사이트입니다.

### 1.2 타겟 사용자
- **주 사용자**: 엔트리를 사용하는 초·중등 학생 (대략 7~15세)
- **보조 사용자**: 학부모, 코딩 교사
- 모바일 사용 비중이 높을 것으로 예상됨

### 1.3 사용자가 페이지에서 달성하려는 목표
1. 자신의 질문 유형에 맞는 적절한 채널을 빠르게 찾아 이동
2. 좋은 질문을 작성하는 방법 학습
3. 코드 캡처 방법 학습
4. 잡담/소통 커뮤니티 발견

### 1.4 도메인/기술 정보
- 배포 URL: `https://help.205.kr/`
- 정적 HTML 단일 페이지 (별도 빌드 도구 없음)
- 언어: 한국어 (`lang="ko"`)
- 운영 주체: "205" (상표 등록된 브랜드) × 엔트리

## 2. 페이지 전체 구조

페이지는 다음 섹션들이 위에서 아래로 배치됩니다. 각 섹션의 **시각적 표현 방식**은 디자이너의 재량입니다.

1. 헤더(상단 네비게이션)
2. Hero (인트로)
3. 질문 채널 안내 (카카오톡 / 밴드)
4. 질문 전 체크리스트
5. FAQ (자주 묻는 질문)
6. 코드 캡처 방법 안내
7. 잡담 커뮤니티 안내
8. 스폰서/광고 영역
9. 푸터
10. (모바일 한정) 화면 하단에 고정되는 빠른 실행 도크

다른 자매 페이지로 **랭킹 만드는 법(`ranking.html`)** 가이드 페이지가 존재하며, 동일 톤앤매너로 디자인되어야 합니다(섹션 9 참조).

## 3. 섹션별 콘텐츠 요구사항

### 3.1 헤더 / 네비게이션
**필수 포함 요소:**
- 사이트 로고 + "엔트리 질문 채널" 브랜드명
- 페이지 내 앵커 이동 메뉴 3개:
  - "커뮤니티" → `#community`
  - "캡처 방법" → `#screenshot`
  - "FAQ" → `#faq`

**기능 요구사항:**
- 스크롤 시 상단에 고정(sticky)되어야 함
- 키보드 접근성: "본문 바로가기(skip link)" 필수

### 3.2 Hero (인트로)
**필수 포함 요소:**

- **서브 카피**: "엔트리 질문을 더 빨리, 더 쉽게! **간단한 질문은 카톡**, **자세한 질문은 밴드 글**로 남겨 주세요. 아래 체크리스트를 보고 올리면 답이 더 빨리 와요."
- **주요 CTA 버튼 2개:**
  - 1차(Primary): "카카오톡 오픈채팅" → `https://open.kakao.com/o/gHwo5vlc`
  - 2차(Secondary): "엔트리 밴드 게시글로 질문" → `https://band.us/@entryband`

**의도:**
- 사용자가 페이지에 들어오자마자 두 핵심 채널로 즉시 이동할 수 있어야 함
- "어떤 질문을 어디에 해야 하는지"의 구분(카톡=간단, 밴드=자세히)이 명확히 전달되어야 함

### 3.3 질문 채널 안내 (Channels)
두 개의 채널 정보 카드 + 안내 노트 1개로 구성됩니다.

**카드 ① 카카오톡 오픈채팅방**
- 제목: "카카오톡 오픈채팅방"
- 설명: "간단한 질문은 카카오톡으로 주시면 빠르게 답변드립니다."
- 링크 주소: `https://open.kakao.com/o/gHwo5vlc`
- 주소 복사 가능한 입력 필드 + "바로 가기" 버튼

**카드 ② 엔트리 밴드**
- 제목: "엔트리 밴드"
- 설명: "복잡한 질문은 밴드에 올려 주시면 자세한 답변이 편합니다. **댓글이 아닌 '게시글'**로 질문을 작성해 주세요."
- 링크 주소: `https://band.us/@entryband`
- 주소 복사 가능한 입력 필드 + "바로 가기" 버튼

**강조 안내(Note):**
> "안내: 밴드에서는 *댓글*이 아닌 *게시글*로 질문을 올려 주세요. 캡처 이미지는 텍스트가 선명한 **화면 캡처**로 첨부하면 검토가 훨씬 빨라집니다."

**의도:**
- 두 채널의 사용 시점 차이를 시각적으로도 구분
- "댓글이 아니라 게시글"이라는 핵심 운영 규칙이 잘 보여야 함

### 3.4 질문 전 체크리스트 (Guide)
**섹션 제목**: "질문 전 꼭 읽어주세요"
**형식**: 번호가 붙은 단계 리스트 (5단계)

각 항목의 콘텐츠:

1. **코드를 함께 올려 주세요.**
   캡처한 이미지나 엔트리 작품 링크가 좋아요. 사진으로 찍은 화면보다 화면 캡처가 더 또렷해요.

2. **무엇을 만들고 싶었는지 적어 주세요.**
   기대한 동작을 한 줄로 써 보아요. 참고한 영상/글이 있다면 링크도 함께요.

3. **이미 해 본 방법을 알려 주세요.**
   시도한 것과 결과를 적어 주면, 같은 방법을 다시 안내하지 않게 도와줘요.

4. **오류가 언제, 어디서 생겼는지 알려 주세요.**
   어떤 화면/오브젝트에서 문제가 생겼는지 쓰고, 스크린샷(또는 짧은 영상)을 올려 주세요.

5. **해결되면 한마디만!**
   먼저 해결됐다면 알려 주세요. 어떻게 해결했는지 남기면 다음 친구들에게 큰 도움이 돼요.

**의도:**
- 어린 사용자도 부담 없이 따라갈 수 있어야 함 (친근한 어투 유지)
- 각 단계가 명확히 구분되어 보여야 함

### 3.5 FAQ (자주 묻는 질문)
**섹션 제목**: "FAQ"
**형식**: 접고 펼 수 있는(아코디언/disclosure) 항목

질문/답변 콘텐츠:

1. **Q. 코드 캡처는 어떻게 하나요?**
   A. PNG 권장, 코드 부분만 크게 보이게 캡처해요. 사진은 빛 반사/흔들림 때문에 글자가 잘 안 보여요.

2. **Q. 밴드에 글을 쓸 때 예시가 있나요?**
   A. [제목] 문제 한 줄 요약 / [본문] ① 의도 ② 현재 상황 ③ 해 본 것 ④ 스샷/영상 ⑤ 엔트리 링크

3. **Q. 카톡이 좋을까요, 밴드가 좋을까요?**
   A. 작은 질문은 카톡, 자세한 문제/버그는 밴드 글을 추천해요.

**기능 요구사항:**
- 클릭으로 펼침/접힘 (HTML `<details>` 권장 — 스크린리더 호환)

### 3.6 코드 캡처 방법 안내 (Screenshot Guide)
**섹션 제목**: "코드 캡처, 이렇게 해요"
**형식**: 두 개의 카드 (Windows / macOS)

**카드 ① Windows**
- 제목: "Windows"
- 본문: `Win + Shift + S`를 누른 뒤, 캡처하고 싶은 영역만 드래그해요. 클립보드에 저장되니 그림판/포토 앱에서 붙여넣기 후 **PNG**로 저장하면 끝!

**카드 ② macOS**
- 제목: "macOS"
- 본문: `⌘ + Shift + 4`를 누르고, 원하는 영역만 드래그해요. 자동으로 바탕화면에 저장돼요. 필요하면 파일 이름만 바꿔서 올리면 돼요.

**의도:**
- 키보드 단축키가 시각적으로 잘 인식되어야 함 (`<kbd>` 요소 사용)

## 6. 접근성(Accessibility) 요구사항

다음은 디자인 시 반드시 고려되어야 합니다:

- **색 대비**: WCAG AA 이상 (본문 4.5:1, 큰 글씨 3:1)
- **포커스 표시**: 키보드 탭 이동 시 명확한 포커스 링 표시
- **Skip link**: 스크린리더/키보드 사용자가 본문으로 바로 이동
- **ARIA 라벨**: 각 `<section>`에 `aria-label`로 의미 부여
- **모션 감소**: `prefers-reduced-motion: reduce` 사용자에게 호버 애니메이션 비활성화
- **시맨틱 HTML**: `header`, `main`, `section`, `article`, `footer`, `nav` 등 적절히 사용
- **버튼/링크 라벨**: 아이콘만 있는 버튼은 반드시 `aria-label` 제공

## 7. 톤앤매너 가이드

콘텐츠 작성 시 유지해야 할 톤(이미 본문에 적용됨):
- **친근하고 부드러운 어투** ("~해요", "~아요" 종결)
- **어린 사용자도 이해할 수 있는 쉬운 단어**
- **명령형 대신 권유형** ("~해 주세요", "~해 보아요")
- 이모지를 과하지 않게 활용 가능 (의미 강화 용도)

시각 디자인 톤은 디자이너에게 위임합니다. 다만 다음을 고려해 주세요:
- **신뢰감**과 **친근함**의 균형 (학생을 위한 도움 페이지)
- 어린 사용자를 위한 **유아적 디자인은 지양** — 초등 고학년~중학생도 거부감 없이 사용 가능한 수준
- 엔트리 플랫폼과의 시각적 연관성을 고려할 수 있으나, 종속적이거나 모방적이지는 않게

## 9. 자매 페이지 (Sister Page) — `ranking.html`

동일 사이트 내 별도 페이지로 **"엔트리 랭킹 만드는 법"** 가이드 페이지가 존재합니다. 메인 페이지(`index.html`)와 **동일한 디자인 시스템**을 공유해야 합니다.

**구성:**
- 헤더 (홈/단계/영상으로 보기/FAQ 메뉴)

## 10. 결과물 요청 형식

다음을 디자이너의 산출물로 받기를 기대합니다:

1. **시각 시안**: 데스크톱 / 모바일 각각의 메인 페이지 시안
2. **자매 페이지(`ranking.html`) 시안** (선택적, 동일 시스템 적용 확인용)
3. **디자인 시스템 정의** (색상, 타이포그래피, 간격, 컴포넌트 스타일)
4. **구현 가이드**: HTML/CSS로 구현 시 참고할 수 있는 자산 또는 설명
   - 단일 HTML 파일에 인라인 `<style>`로 작성되는 구조이므로, 외부 라이브러리 의존을 최소화한 vanilla CSS 가이드 선호
5. **에셋 제공** (필요시): 일러스트, 아이콘, OG 이미지(`1200×630`) 등
